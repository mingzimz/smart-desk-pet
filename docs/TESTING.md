# 测试与 Windows 验收

## 本次验证记录（2026-09-26）

- 环境：Windows、Python 3.14.6、PySide6 / Qt 6.11.0、pytest 9.0.3。
- 自动化：40 项测试通过，包含独立子进程启动、退出、保存和锁释放。
- 代码质量：`ruff check` 和 `compileall` 通过。
- 界面：已生成并人工查看实际 Qt 组件的离屏预览，确认中文显示及主要布局。
- 尚未验证：真实 Ollama/远程模型、原生 Windows 托盘和透明合成、跨 DPI 多屏、干净系统运行与长期资源占用。
- 打包：已提供 PyInstaller spec、PowerShell 构建脚本与 Windows CI；本次环境未安装 PyInstaller，未生成或运行 EXE。

## 自动化

```powershell
python -m ruff check .
python -m pytest -q
python scripts/render_preview.py
```

测试用 Qt offscreen 平台，不要求桌面出现真实窗口。HTTP 测试使用进程内本地替身服务，不会访问真实模型或收费 API。

测试范围：情绪阈值、恢复和边界；配置校验、损坏备份、原子替换失败；记忆隔离、容量和恢复；上下文预算；两类 API 的真实异步 HTTP 请求与解析；取消、超时、异常响应；内置透明动画和单图导入；越界角色路径；点击与拖拽区分；设置、人设切换、对话持久化和隐藏暂停。

`render_preview.py` 用实际 Qt 组件生成 `docs/preview.png`；聊天中的展示文本是脚本注入的 UI 示例，不代表模型回答测试。离屏插件可能不枚举系统字体，脚本会在 Windows 上显式加载已有微软雅黑用于预览，不向项目复制字体文件。

## 必须进行的人工验收

### 桌面与托盘

1. 在 Windows 10/11 真正桌面启动，确认角色背景透明、无边框，切换前台应用后仍置顶。
2. 单击打开聊天并提升心情；拖动不会误触聊天，拖到边缘会保持可恢复区域。
3. 托盘右键隐藏/显示；双击切换；关闭聊天和设置仍保持桌宠运行；菜单退出后进程消失。
4. 用不同 DPI 的双屏拖拽，重启、拔掉副屏、休眠唤醒后检查角色可见性。当前启动和拖拽结束会限制位置，运行时屏幕拓扑变化仍需测试和进一步完善。
5. 修改不透明度至 20% 后仍能通过托盘恢复 100%。

### 角色与设置

1. 两个内置角色分别切换；观察四状态，修改动画速度并重启核对。
2. 导入透明 PNG、带背景 JPG，确认透明度和原背景按预期保留；重启仍可选择导入角色。
3. 使用损坏图片和超大图片，得到可读错误，原角色继续运行。
4. 分角色修改人设，反复切换确认各自保留；取消设置不改变当前配置。
5. 在临时数据副本上损坏 config.json / memory.json；确认备份和提示，再检查默认运行。

### 真实模型

1. 用已下载模型接入 Ollama，至少完成多轮对话；拖拽和托盘在推理时保持响应。
2. 接入真实 OpenAI 兼容服务；验证模型名、Base URL、Key 环境变量和会话 Key。
3. 分别模拟错误地址、认证失败、模型不存在、服务断开和慢响应；输入保留，可修改配置后重试。
4. 请求途中取消、切换角色、应用设置、退出；旧回复不能写入其他角色记忆。
5. “记住：我喜欢猫”在成功回复后持久保存；重启有近期上下文，清除后不再带入。
6. 检查日志与 JSON 没有 API Key；若使用远程服务，明确知道上下文会发送给所选服务。

### 构建与稳定性

1. 安装开发依赖后运行 `scripts/build.ps1`，在未安装 Python 的干净 Windows 机器启动完整 dist 目录。
2. 确认用户数据位于 AppData，应用目录只读时仍可运行；同数据目录二次启动不会出现并发写入。
3. 连续运行 4 小时，检查 CPU/内存、隐藏状态资源占用、对话积累及反复切换。
4. 检查发布包大小、签名需求、Qt/PySide6 和正式素材的分发许可要求。

## 验证边界

本项目的测试不会自行调用真实模型、安装 Ollama、下载模型或配置供应商账户。自动化通过不等于真实桌面透明合成、托盘、跨 DPI 和干净系统打包验收通过。发布前请为以上人工场景记录系统版本、模型名、日期和结果。
